# スライド作成ルール（正典）

consulting-slide-builder スキルが、スライドを作る前に必ず全文を読むルール集。スキル本文と食い違う場合は、このファイルを優先する。
レビューで受けた指摘は、一般化して末尾の「G. 追加ルール」に1行ずつ足し、CHANGELOG.md に記録する。

## 着手前の確認

- 目的・成果物・範囲を3〜5行で示し、合意してから作る。
- 全ページについて「伝えたいこと」か「相手に決めてほしいこと」を1行で書く。書けないページは削る。
- 依頼者が決めたページ構成は勝手に組み替えない。組み替えるなら理由を添えて確認する。
- 定例資料は前回の**最終版**（下書きではない）を土台にし、変わった部分だけを直す。
- 同じ型を5枚以上並べるときは、代表の1枚を先に作って確認してもらう。
- 背景が分からない依頼は、デッキにせず1枚の論点整理で返す。

## A. メッセージラインの規定（最重要）

### A-1. 形式

- 1スライド1メッセージ。メッセージは**ちょうど2行**（游ゴシック UI 20pt・標準の太さで約68〜72字、各行をほぼ埋める）。太字にしない（紺・20pt・2行で本体より強く見えるため。2026-10-27）。1行で終わるメッセージは情報不足、3行になるメッセージは詰め込みすぎとみなす。文字数はスライド幅と英数字の量で変わるため、最終的には実際の表示で2行ちょうどかで判断する。
- 構成は「**事実（数字入り）＋示唆（だから何か）**」。例：「○○の輸送密度は10年で4割減少し、運賃だけでは維持費を賄えない。存廃ではなく上下分離を含む運営形態の転換を検討すべき局面にある」
- **句点**：メッセージが2文なら1文目の末尾に「。」を付け、2文目（最後）の末尾には付けない。1文なら末尾に付けない（自作の書式 HG_pptFMT の基本事項）。
- 文末は「である調」で統一する。体言止め、疑問形、「〜について」、「です・ます」は使わない（相手への依頼・質問のページだけは例外）。
- **単独で読める**こと。「この」「その」「上記」で他のページを指さない。
- 主張を持たないページ（表紙、目次、章扉、会社紹介）だけは、素のラベル題でよい。
- 2行にするのは、文字を縮めて詰めるためではない。意味の切れ目で改行し、数文字だけの折り返しを作らない。

### A-2. 洗練させるための書き方

| やること | やらないこと |
| --- | --- |
| 主語と述語をはっきり書く | 「〜の状況」「〜の動向」などトピックだけを書く |
| 具体的な数字・比較対象を入れる（「2倍」「3割」「全国平均の半分」） | 「大きく」「様々な」「一定の」などの曖昧語 |
| 示唆は本体で証明できる範囲に留める | 本体にない事実をメッセージラインで主張する |
| 要素は2つまで（事実と示唆） | 「A、B、C、D」と羅列する（羅列は本体で示す） |
| 専門用語は読み手が普段使う言葉にする | 括弧書きの補足、略語の初出 |
| 前のスライドとつながる言葉を意識する（「一方で」「要因は」） | 毎回同じ言い回しで始める |
| 個数は、数そのものが主張のときだけ書く。書いた数は本体の番号と一致させる | 「3つの理由」「5つの施策」のように個数だけを示す |
| 言い切りの強さを根拠に合わせる。競合の記述は中立に | 根拠より強い断定（「唯一」「必ず」「圧倒的」） |
| 主張から書き出す | 「現状と課題：」のような分類名の前置き、「そこで」「つまり」などの話し言葉で始める、直前の依頼文の言い換え |

### A-3. メッセージラインの作り方

1. ゴーストデッキのタイトルを出発点に、A-1・A-2に沿って磨く。意味が変わる変更はしない。
2. 全メッセージラインを一覧にし、「メッセージライン一覧」として提示する（各行に文字数を付記）。
3. 一覧だけを上から読んで、結論・理由・打ち手が分かるかを自己確認する。話が飛ぶ箇所は、言葉の修正かスライドの追加を提案する。
4. **10秒テスト**：メッセージラインだけを10秒読んで、何を言いたいスライドか分かるか。**60秒テスト**：本体を含めて60秒で理解できるか。どちらかに失敗したら直す。
5. **タイトルと本体の対応**：メッセージラインの「事実」の数字は本体のどこかに必ず現れ、「示唆」はその数字から一段で言える範囲に留める。本体にメッセージと無関係な要素が残っていたら削る。
6. ユーザーの承認を得てから本体の作成に進む。

## B. 見た目の規定（NRIの骨格＋McKinseyの抑制）

### B-1. スライドサイズと余白

- 27.52 × 19.05 cm（780 × 540 pt、A4横相当）。指定があれば16:9。
- 全要素をガイド線（下の表）にそろえ、メッセージラインとボディの位置は全ページで動かさない。
- 本体は詰め込まず、余白を残す。余白がないのは情報が多すぎるサイン。
- 位置の基準（pt、780×540基準）：メッセージブロック 上20.6〜94／区切り線 105／ボディ（本体の見出し） 117〜139／本体 143〜486／注記・出所 494〜／ページ番号 右下。本体は12分割のグリッドに沿って置き、左右2つのエクジビットは6:6か7:5で分ける。

**ガイド線**（2026-10-22 追加。値は PowerPoint の［ガイド］の表示と同じ「スライドの中心からの距離、cm」。横のガイドは中心より上が＋、縦のガイドは中心より右が＋）

| No. | ガイド | 向き | 値 | 上端・左端からの位置 | そろえるもの |
| --- | --- | --- | --- | --- | --- |
| ① | スライドタイトルの上端 | 横 | +8.80 | 上から 0.725 cm | メッセージブロック（紺の縦バー・章名）の上端 |
| ② | ボディ部分の上端 | 横 | +5.40 | 上から 4.125 cm | 本体の見出し（スライドタイトル14pt、または左右の欄の見出し）の上端 |
| ③ | 資料内容の左端 | 縦 | −13.20 | 左から 0.56 cm | すべての要素の左端（縦バー・見出し・表・図・注記・出所） |
| ④ | 資料内容の右端 | 縦 | +13.20 | 左から 26.96 cm（右から 0.56 cm） | すべての要素の右端（区切り線・表・図・ステッカー・ページ番号） |
| ⑤ | 資料の中心 | 縦 | 0 | 左から 13.76 cm | 左右2分割の境目、中央にそろえる要素（表紙・大型数値の対比） |

- PowerPointでは［表示］→［ガイド］に✓を入れて作業する。エビデンス（本体）はガイド線からはみ出さない。どうしてもはみ出すときは、上端（②）は動かさずに下へ伸ばす（メッセージとエビデンスの距離を全ページで一定に保つ）。
- ガイド線はスライドマスターに入れる（本文のスライドでは動かない。動かすときは［表示］→［スライド マスター］）。新しいデッキには `python3 scripts/add_guides.py deck.pptx` で入れる。見本デッキ（`patterns/pattern-deck.pptx`）には入っている。
- 要素を③〜④の外に出さない。表・図・区切り線・ステッカーの右端を④に、左端を③にそろえる（`check_deck.py` が③④の外を FAIL、①②にそろっていないページを WARN）。
- メッセージブロックは①から始め、ボディは②から始める。②より上（メッセージブロックと区切り線の間）に本体の要素を置かない。
- 16:9 で作るときも、ガイド線の考え方（①②の上端、③④の左右端、⑤の中心）は同じにし、値はスライドの大きさに合わせて決め直す（`add_guides.py` の `GUIDES` を変える）。

### B-2. フォント（本文14pt・図の文字12pt・注記9ptの3段）

**本文・読み取りは14pt、図の中の文字（ラベル・軸・表の数値）と補足は12pt、注記・出所は9pt**の段差を付ける。図を大きく、文字を一段小さく見せるため（2026-10-27、MCK04の実測で本体の文字が16・14・12・10ptの4段だったことを受けて変更）。12pt未満を使ってよいのは注記・出所・ページ番号と章名だけ。

| 区分 | 用途 | フォント | サイズ |
| --- | --- | --- | --- |
| 本体 | メッセージライン | 游ゴシック UI Regular（**太字にしない**） | **20 pt**（全ページ同一、2行） |
| 本体 | スライドタイトル（本体の見出し、チャート見出し） | 游ゴシック UI Bold | **14 pt** |
| 本体 | 本文、キーメッセージ欄・読み取り、ポンチ絵の名前 | 游ゴシック UI Regular | 14 pt |
| 本体 | チャートの数値ラベル、系列名、項目名（軸ラベル）、表の数値・行見出し、矢印のラベル、紺の注釈（CAGR等） | 游ゴシック UI／Arial | **12 pt** |
| 本体 | 言いたい数値を大きく見せるとき（大きな数字・合計） | Arial Bold | 24–32 pt |
| 注釈・補足 | 章名（トラッカー）、補足説明の一文、チャート見出しの単位・期間の括弧書き | 游ゴシック UI Regular | 11–12 pt |
| 注釈・補足 | ステッカー（「試算」等） | 游ゴシック UI Regular | 11 pt |
| 注釈・補足 | 注記（注））、出所（出所））、ページ番号 | 游ゴシック UI Regular | 9–10 pt |

- スライドタイトルは本文と同じサイズなので、太字＋下の細いグレー線で本文と区別する。
- 数値・英字はArialで、同じ行の和文と同じサイズにする。
- 収まらないときは、上の段より**文字を小さくしない**（本文を12ptに落とす、図の文字を10ptに落とす、はしない）。文言を削る、要素を減らす、スライドを分けるの順で対応する。
- 游ゴシック UIが使えない環境ではメイリオで代替し、報告する。フォントは和文＋欧文の2種類まで。文字の強弱は色よりも太字とサイズで付ける。

### B-3. 配色（「グレーで描き、1点だけ紺」）

本体で使う色は、次の指定色だけにする。**「基」の3色（Navy・Blue5・Gray2）を基本とし**、それ以外の色は下の役割に合うときだけ使う。

| 名前 | RGB | HEX | 役割・使う場所 |
| --- | --- | --- | --- |
| **Navy（基）** | 0 15 120 | #000F78 | 唯一の強調色。メッセージライン、左の縦バー、本体で言いたい**1点** |
| Blue1 | 60 100 170 | #3C64AA | 補助。系列が多く、Gray2・Gray1・Blue4 で塗り分けが足りないときだけ |
| Blue2 | 131 160 211 | #83A0D3 | 同上 |
| Blue3 | 114 223 240 | #72DFF0 | 同上。明るい水色なので小さな面積に限る |
| Blue4 | 224 238 248 | #E0EEF8 | ごく薄い背景（目標までの帯、パネル）、3番目の系列 |
| **Blue5（基）** | 193 221 241 | #C1DDF1 | 注目箇所を示す面（注目の行・列の帯、強調の囲みの塗り）。1スライド1か所まで |
| Gray1 | 204 204 204 | #CCCCCC | 比較対象の系列、図形の線、区切り線 |
| **Gray2（基）** | 127 127 127 | #7F7F7F | 文脈として見せたい系列、矢印、アイコン、基準線 |
| White | 255 255 255 | #FFFFFF | 背景、濃い塗りの上の文字 |

文字の色は次の3つだけにする。

| 役割 | RGB | HEX | 使う場所 |
| --- | --- | --- | --- |
| **文字（基本）** | 63 63 63 | #3F3F3F | 本文・見出し・ラベル・章名・注記・出所・ページ番号など、全ての文字 |
| 強調の文字 | 0 15 120 | #000F78（Navy） | メッセージライン、本体で強調する1点 |
| 反対色の文字 | 215 50 50 | #D73232 | Navyと逆の意味（悪化・未達・リスク）を強調するときだけ |

- **強調は1スライド1点**。Navyを使うのは「メッセージが指している場所」だけ。メッセージを読んだ人の目が、次にNavyの箇所へ行くようにする。
- 強調しない系列・図形・線はGray2とGray1で描く。系列が3つ以上なら Gray2 → Gray1 → Blue4 の順に足し、それでも足りないときだけBlue1〜Blue3を使う。
- 反対色（#D73232）は、悪化・未達そのものがメッセージの場合に、その1点をNavyの代わりに示すときだけ使う。同じスライドでNavyの強調と並べない。
- 文字は全て#3F3F3Fにそろえ、補足・注記も同じ色にする。文字の階層は色ではなく大きさと太字で付ける。
- 指定色以外（黒#000000、上にないグレー、赤・オレンジ・緑など）は使わない。
- 塗りつぶしの色付きボックス、Navyの帯に白文字の見出し、色付きパネルを並べる構成は使わない（強調が分散するため）。区切りは細い線と余白で作る。
- 確認方法：「3秒見て、強調箇所が1つだけ目に入るか」「グレースケールで印刷しても読めるか」。

### B-4. ページ構造（本文スライド）

1. **メッセージブロック（NRIの骨格）**：左端に幅約4 ptの紺の縦バー。その右に、上段「章番号＋章名」（11–12pt、#3F3F3F）、下段「メッセージライン」（20pt、標準の太さ、2行、紺）。ブロックの下に細いGray1の線。
2. **本体**：スライドタイトル（14pt太字の#3F3F3F＋下に全幅の#3F3F3F 1.25ptの線。H-2）と、エクジビット（チャート／図解／表）を1つ。
3. **キーメッセージ欄（任意）**：本体の右端または下端に、読み取るべき点を1〜3個（14pt）。各項目2行以内。枠は付けず、細い線で区切る。
4. **注記・出所**：左下。「注）」「出所）」の順（D-3）。
5. **フッター**：右下にページ番号。著作権表示・ロゴはユーザー自身の組織のもの（未指定なら空欄）。

スライドタイトルは「何のデータか・単位・期間」を示す見出しの役割に限る。それ以外の**説明行は置かない**：メッセージライン直下の言い換え、図表の上の飾りラベル、画像の下のキャプション、「POINT」「まとめ」の帯は使わない。

### B-5. その他のページ

- **表紙**：白地。左寄せでタイトル（紺、大きく）・副題・日付・組織名。写真はユーザーが用意したもののみ。
- **目次・章扉**：番号＋章名（16pt以上）を細い線で区切って縦に並べる。当該章だけNavy・太字、他は#3F3F3Fの細字。
- **エグゼクティブサマリー**：各章のメッセージラインを太字1行＋根拠の数字1行で並べ（いずれも14pt以上）、最後の提言だけを紺にする。文字主体のページはここだけ。収まらなければ2ページに分ける。
- **デッキ全体の構成**：表紙 → エグゼクティブサマリー → 目次 → 章ごとの本文 → 提言・次のステップ → 参考資料（Appendix）。本文で使わなかった分析は参考資料へ回し、本文の枚数を増やさない。
- **目次・章扉の要否**：本文が11枚以上なら目次（全体マップ）と章扉を置く。10枚以下なら置かず、章名のトラッカーだけで位置を示す。
- **締め**：「次のステップ」は、実際に依頼・合意事項があるときだけ作る。提案前の資料は相手への依頼ではなく、こちらができることで締める。正式提案は費用と次段階に進む判断基準で締める。裏表紙を置く場合は組織名と連絡先だけにする。

### B-6. 禁止事項

- NRIのロゴ、社名、著作権表示、スローガンを入れない。NRIが作成した資料に見せない。参考にするのは書体・主色・ページの骨格のみ。
- 影、グラデーション、3D、絵文字、多色のアイコンやクリップアート、装飾だけの写真、過剰な角丸。
- 塗りつぶしブロックを積んだピラミッド図やSmartArt風の図（安っぽく見える）。階層は線と文字で表す。
- 段落書きの長文。
- 下部の結論帯（メッセージラインの言い直し）、理由のない囲み・塗り、どこにも結びつかない浮いたラベル。塗りは凡例で意味を言えるときだけ使う。
- 本文を14pt未満、図の文字を12pt未満にして詰め込むこと。

## C. 本体の規定（簡潔・視覚的）

### C-1. 本体の原則

- 本体に置くのは、メッセージラインを証明する要素だけ。「あると良い情報」は後ろの参考資料へ回す。
- **文字より図**。数字はチャート、関係は図解（ポンチ絵）、比較は表で示す。箇条書きだけのスライドは作らない。
- 文字量の目安：図だけのページは本体の文字（チャートのラベルと注記・出所を除く）を120字程度までにする。図の右に読み取り帯（太字の一文＋根拠2〜3文を2段、P54）を置くページは、帯を含めて300〜450字が公開資料（MCK04、本体の文字の中央値約320字）の水準。図の中の1つの要素に添える文は2行以内。450字を超える場合はスライドを分ける。
- 説明に60秒以上かかるスライドは分割を提案する。
- **ピラミッド構造**：メッセージライン（結論）→ スライドタイトル（何で証明するか）→ 本体（根拠）→ 注記・出所（前提）の順に、上から下へ抽象から具体に降りる。本体の中で結論を言い直さない。
- エクジビットが2つ要る場合は**左右に並べる**（上下に積まない）。左右の見出しの高さと下端をそろえ、結論側（右）だけに紺を使う。3つ以上要るならスライドを分ける。
- **左に前提、右に帰結**。前提・定義・図は左、そこから言えること・具体例・説明は右。強い因果があるときだけ、左右の間にグレーの塗り三角を1つ置く。左右の見出しは単独で意味の通る名詞句にする（「だから〜」で始めない）。
- 右で論じる項目は、左の図のどこの話かを番号や帯で対応させる。図にない項目を右で論じない。
- 表は1枚に1つまで。比較表は**行＝観点、列＝比較対象**で統一する。行ごとの意味合いは右の別欄ではなく、表の列として持たせる。
- 比較でないものは表にしない。重なりはベン図、日程はガント、工程は矢羽、関係者の連携は流れ図、業務フローはスイムレーン（導入前の現状に提案物を混ぜない）。
- **スカスカも不可**。内容が少ないのに要素を引き伸ばして埋めない。情報を足すか型を変え、それでも少なければ中央にまとめる。本体の4割以上が空いていたら見直す。

### C-2. 本体の型（この中から選ぶ）

| 型 | 使う場面 | 強調の置き方 |
| --- | --- | --- |
| 単一チャート | 数字で証明する場合の基本形 | 言いたい棒・線だけ紺、差分やCAGRを紺の注釈で |
| チャート＋キーメッセージ欄 | チャートから読むべき点が2〜3ある | 欄の番号とチャート上の番号を対応させる |
| 左右比較 | Before/After、自社と他社、現状とあるべき姿 | 右（結論側）だけ紺 |
| ポンチ絵（関係図） | 関係者の関係、お金・モノ・情報の流れ、仕組み | 変化する箇所・課題の箇所だけ紺 |
| プロセス／ロードマップ | 手順、スケジュール | 今回決める段階・判断点だけ紺 |
| ロジックツリー | 要因の分解、論点整理 | 効いている枝だけ紺 |
| 2×2マトリクス | 優先順位、ポジショニング | 推奨象限の文字と項目だけ紺 |
| 評価表 | 選択肢・事例の比較 | 推奨する列だけ紺の細枠。評価はハーベイボール（グレー）。表は4列4行程度まで |

### C-3. ポンチ絵の作法

- 登場人物・組織は、単色の線画アイコン（グレー）＋下に短い名前（14pt）で表す。アイコンの絵柄はデッキ全体で統一する。
- 矢印には「何が流れるか」（資金、データ、人など）を短く書く（12pt）。
- 要素は6つ以内。各要素の文字は12字以内。
- アイコンはリポジトリの `templates/icons/`（線画のSVG 70種、一覧と使い方は `docs/icons.md`）から選ぶ。グレーを基本とし、紺は変化する主体1つだけ。足りない場合も同じ線画の素材集（Lucide）から選び、別の素材を混ぜない。多色のイラストは使わない。
- 矢印・線・括弧・判断点などの記号は `docs/symbols.md`（見本デッキの S01〜S04）の使い分けに従う。
- 流れは左から右（文字の多い箱の連なりは上から下）。逆流させない。要素の配置を先に決めてから矢印を引く。
- 線は交差させず、重ねない。直線と直角で結び、曲がりは1回まで。1つの図の中で矢印の意味（流れ・因果・時間）を混ぜない。意味が違う線を使うなら凡例を付ける。
- 同じ階層の要素は同じ形・同じ大きさにそろえる。関係（包含・隣接・交差・分離・並列）は線より先に配置で表す。番号は左から右、上から下（または時計回り）に振る。

### C-4. 論理の運び（デッキ全体）

- **1枚で論理を1段だけ進める**。2段以上を詰めない。
- 課題を示したページの後には、それを解くページを対で置く（「〜は、…で越えられる」）。SCRで書く場合、課題は未達の原因だけを書き、解決は課題と1対1で対応させる。
- エグゼクティブサマリーや冒頭の表で使った行立て・用語・順番は、深掘りページでも同じにする。
- 論点を番号で宣言したら、後続ページの章名トラッカーに同じ番号を付け、どの論点の話かを示す。
- 判断を求める資料では、問いが求める形で答えるページを置く（採算を問われたら、投資を含む期間の損益で答える）。論点整理や検証計画の段階では、答えを出したように言い切らない。
- 読み手の判断を左右する分析（前提が崩れる条件、失敗の理由、感度分析）は参考資料に回さず本文に置く。
- 選んだ案の詳細は、比較して選ぶページより後に置く。

### C-5. 文章の作法

- **数字・記号の書き方**：数字は半角。3桁ごとにカンマで区切る（西暦・年度・番号・電話番号には付けない）。括弧（）は全角。
- 「連携強化」「DX推進」「自動化」「高度化」だけで済ませず、**誰が・何を・どうする**かを書く。
- 字数を削るときも主語と述語は残す。助詞を抜いた圧縮語（「需要減少対応策検討」）にしない。
- 1つの概念に1つの用語。略語は初出で説明するか、使わない。完了形と進行形（「導入した／導入中」）を取り違えない。
- AIらしい言い回しを避ける：「〜を実現」「〜を推進」「重要な役割を果たす」「多角的」「包括的」「シームレス」「〜と言えるでしょう」「さらなる」の多用、体言止めの連続。具体的な事実か数字に置き換える。語彙・構文・締めの全リストと仕上げ前の確認は `rules/ai-wording.md`。

## D. チャートとエビデンスの規定（McKinsey・BCG流、think-cell風の仕上がり）

### D-1. メッセージ別のチャート選択

チャート型の誤りは分析の誤りとみなす。メッセージから逆算して選ぶ。迷ったら、**メッセージを証明できる最も単純なチャート**（多くは横棒か縦棒）を選ぶ。

| 伝えたいこと | 使うチャート | 要点 |
| --- | --- | --- |
| 時系列の変化 | 縦棒（期間が少ない）／折れ線（期間が長い） | CAGRを矢印で注記。見通しは淡色や斜線で区別 |
| 順位・大小比較 | 横棒（降順） | 注目対象だけ紺、他はグレー |
| 構成比 | 100%積上げ棒 | 系列は5つ以内。Gray2・Gray1・Blue4の順で塗り分け、注目の1系列だけNavy |
| 構成と規模の両方 | マリメッコ（メコチャート） | 幅＝規模、高さ＝シェア |
| 増減の要因分解 | ウォーターフォール | 始点・終点はGray2、要因はGray1、最大要因だけNavy。増減は「＋」「−」のラベルで示す |
| 2変数の関係 | 散布図／バブル | 平均線で象限を切り、注目点だけ紺 |
| アンケート結果 | 横の100%積上げ（属性別の行） | 設問文とn数を必ず記載 |

- 円グラフ・レーダーチャート・二軸グラフは原則使わない（使う場合は理由を報告）。
- ラベルを12ptで書ける量に絞る。棒は最大10本程度、折れ線の系列は3本まで。超える分は「その他」にまとめるか、数値ラベルを注目点だけにする。
- **選ぶ順番（Zelazny『Say It With Charts』）**：①メッセージを決める → ②比較の種類を見極める（構成・項目・時系列・度数分布・相関の5種類）→ ③形式を選ぶ。形式から入らない。時系列は区切りが7程度までなら縦棒、それより多ければ折れ線。
- 円グラフを例外的に使うのは、区分が2〜3つで「全体に占める割合」そのものが主張のときだけ。区分は大きい順に12時から時計回り、6区分まで。複数の円を並べて比べない（100%積上げ棒にする）。複数回答（合計が100%を超える）は円グラフ・100%積上げにしない。
- 二軸グラフの代わりに、単位ごとに2つの図を左右に並べる（1つの図に1つの単位）。軸の取り方で印象を作れてしまうため。
- マリメッコは区分を少なく保つ。面積は読み取りにくいので、規模とシェアの片方しか議論しないなら棒に置き換える。

### D-2. チャートの作法（think-cell風）

- **見出し**：「何の」を14pt太字、「単位・期間」を括弧書きで11–12ptで書く。例：「国内○○市場規模の推移」＋「（億円、2015–2030年度）」。解釈はメッセージラインに書き、見出しには書かない。
- **線を減らす**：罫線なし。縦軸は消して棒の上に数値を直接書く（12pt）。横軸は細いグレーの基線1本だけ。
- **直接ラベル**：凡例は使わず、系列名を線の端・積上げの横に直接書く（12pt）。
- **棒の形**：棒の幅は間隔より太く。棒グラフの軸は0始まり。
- **注釈は1つ**：CAGRの矢印、差分の括弧（「+2.1倍」）、変曲点の吹き出しのどれか1つを紺で12pt（太字）で。数値を本文とラベルで二重に書かない。
- **見通し・推計**：実績より淡い色か斜線にし、年度に「（見込）」「（予測）」。
- **ステッカー**：数値の性格を右上に小さく（11pt）、グレーの細枠で表示（「試算」「暫定」「イメージ」「議論用」）。
- グラフ・図形は編集可能なネイティブオブジェクトで作り、画像にしない。元データはエビデンスExcelの「グラフ用」シートと一致させる。
- 数値の符号・単位・印（＋−、pt、倍、–、ハーベイボール、✓、注記など）は `docs/symbols.md` に従う。負の数は「−」で書き、▲・△を符号に使わない。
- **軸**：棒グラフの縦軸は必ず0から始め、途中を省略しない（省略が要るなら棒をやめて折れ線か点にする）。折れ線・散布図は0から始めなくてよいが、そのときは目盛りを残して範囲を示す。軸の範囲を主張に合わせて恣意的に切らない。上限のある指標（割合・達成率）は0〜100%の全幅で描く。
- **目盛線**：数値ラベルを全部の棒に付けるなら縦軸と目盛線は消す。目盛りを残す図（折れ線・散布図）は、目盛線を消すか淡いGray1の細線にし、データより目立たせない。刻みはきりのよい数にする。
- **単位**：見出しの括弧書きに「単位、時点」の順で書く（例「（億円、2015–2025年度）」）。軸の単位と見出しの単位を二重に書かない。1つの図に1つの単位。
- **並び順**：項目は大きい順、「その他」は最後。時系列は古い順に左から右（縦の表では上から下）。複数の図で同じ項目を扱うときは、並び順を全ての図でそろえる。
- **差分とCAGRの注記**（think-cell の作法）：差分矢印は、絶対差か相対差（%・pt・倍）かを書き分ける。CAGRの矢印は合計値の棒どうしを結び、矢印のラベルに期間を書く（「年平均＋6.7%（2019→2025年度）」）。CAGR＝（終点÷始点）^（1÷期間数）−1、期間数は「終了年−開始年」（2019→2025年度は6期間）。検算表で再計算する。
- **ウォーターフォール**：始点と終点は全高の棒、増減は同じ基準線から浮かせ、棒どうしを細い点線でつなぐ。増と減は色ではなく符号と位置で示す（増減の色分けが要るならGray2とGray1）。
- **見通し・推計**：実績と同じ図に入れるときは、年の後に「（見込）」「（予測）」を付け、塗りを淡くするかラベルで区別する。推計の方法は注記に書く。
- **色だけに頼らない**：色の違いだけで系列を区別させない。直接ラベル・位置・形を併用し、グレースケールで印刷しても読めるかを確かめる。

### D-3. エビデンスの示し方

- **全数値に出所**：出所のない数値は載せない。根拠がない箇所は反対色（#D73232）で【要確認】（仕上げ時に全て解消する前提の作業表示）。
- **出所の書式**：`出所）発行主体「資料名」（発行年月）`。複数は「；」で区切る。加工した場合は「…を基に作成」、独自分析は「…を基に分析」。
- **注記**：定義・前提・例外は本文中に肩文字（1, 2 …）を付け、「注）1. …」と出所の上に書く。年と年度、名目と実質、税込と税抜を区別する。
- **アンケート**：設問文の要旨、n数、調査時期、複数回答かどうかを書く（注記扱い）。
- **定性情報**：ヒアリングの発言は「」で引用し（14pt）、発言者を属性（例：地方鉄道事業者 経営企画部長、補足扱い）で示す。個人名は出さない。
- **裏付けの厚み**：重要な主張は、定量データ＋事例（または有識者発言）の2種類以上で支える。ただし1スライドに詰めず、必要ならスライドを分ける。
- **数値の書式**：単位は見出しにまとめ、桁区切りを入れる。有効数字は2〜3桁、比率は小数点以下1桁まで。同じ指標は全ページで同じ単位。合計と内訳が丸めで合わない場合は注記する。
- **内訳まで出す**：合計だけでなく内訳を示す。一覧は全件を載せ、版面に入らなければ参考資料に回して本文から参照する。
- 未確定の金額・工数は「仮」と明記するか、載せない。
- **見出し語は「注）」「出所）」に統一する**（NRIの書き方）。「出典：」「資料：」「Source:」を1つのデッキで混ぜない。英文のデッキは「Note:」「Source:」の順。
- **注は番号で本文と対応させる**：本文の該当語に肩番号（1, 2 …）を付け、「注）1. …　2. …」と出所の上に置く。その図表に不可欠な情報だけにし、他のページの注を参照させない。
- **加工の度合いを書き分ける**：
  - 数値・図表をそのまま載せた → `出所）発行主体「資料名」（発行年月）`
  - 数値を使って図を作り直した → `…を基に作成`
  - 数値を組み替え・計算した → `…を加工して作成`（政府標準利用規約の書き方。加工した旨は出典と別に書き、国や発行元が作ったように見せない）
  - 自社で推計・分析した → `…を基に推計`／`…を基に分析`（推計の方法は注に書く）
  - 自社の調査 → `出所）当社「調査名」（実施年月、調査方法、対象）`
- **たどれる形で書く**：発行主体・資料名・発行年月は必須。「出所）インターネット」のような、元の資料にたどれない書き方をしない。ウェブ資料は `発行主体「ページ名」（更新日）、URL（閲覧日）` まで書く。委託調査報告書は `発注者「報告書名」（受託者、発行年月）p.◯`、決算資料は `会社名「◯年◯月期 決算説明資料」（発行年月）`。発行年月の書き方（2026年3月／2026/3）はデッキ内で1つにそろえる。
- **複数の出所**は「；」で区切って全て書く。4つ以上で書き切れないときだけ主なものを書き「等を基に作成」とし、全件は参考資料に回す。
- **孫引きをしない**：他の資料が引いた数字は、原典を開いて確かめてから原典を出所に書く。原典に当たれないときだけ `原典（◯◯）、△△より引用` と両方を書き、【要確認】を付ける。
- **他者の図をそのまま貼らない**：他社・他機関が作った図は、元のデータから本ルールの書式で描き直し「…を基に作成」と書く（見た目がほぼ同じなら複製とみなされうる）。出所を書いても転載の許可の代わりにはならない。写真・イラスト・ロゴなど第三者に権利がある素材は、利用規約で自由に使えるとは限らないので、権利を確かめてから使う。
- **引用の要件**（著作権法32条・48条）：自分の主張が主で引用が従、引用部分をかぎ括弧や枠で区別し、出所を明示し、引用する必然性がある範囲に限る。国・自治体が広報のために公表した資料は、転載禁止の表示がなければ説明の材料として転載できるが、出所は必ず書く。
- **前提の注記**：年と年度を混ぜない（年度は「4月〜翌3月」と注記）。名目か実質か（実質なら「2015年価格」など基準年）、税込か税抜か、為替の換算レート、対象範囲（「海外を除く」など）を、数値が変わる前提として注に書く。
- **アンケートの注記**：設問文（回答形式「1つ選択」「複数選択可」を併記）、n数、調査時期、調査主体、調査方法と対象を書く。複数回答は「合計は100%を超える」と注記する。n＝30未満の区分は「参考値」と書いて見た目でも区別する。
- 統計表の記号は `docs/symbols.md` に従う（該当なしは「—」、不詳は「…」）。出所の統計が独自の記号を使っているときは、その凡例を注に書く。
- 書き方の例と根拠の一覧は `docs/chart-and-source-notes.md` を参照する。
- スピーカーノートに、使ったエビデンスID・使ったパターンID・参考にしたページID（patterns/patterns.md）を全て記載する。

### D-4. 検算（最後まで通す）

AIが作った資料で最も差が出るのは、見た目ではなく数値の整合である。生成後に必ず行う。

- スライドに出る**計算した数値**（合計、構成比、差分、倍率、CAGR、回収年数、損益）を全て、エビデンスExcelの元データからスクリプトで計算し直し、表示値と一致するかを確かめる。結果は「検算表」（スライドNo.・表示値・再計算値・一致）にまとめる。
- 図に書いた前提条件と、計算に使った前提条件が同じかを確かめる（期間、対象、単価、名目／実質）。
- 現金にならない効果（時間削減の金額換算など）は、投資回収・キャッシュフローの計算に入れない。入れる場合は別建てにし、注記する。
- メッセージラインの数字と本体の数字、エグゼクティブサマリーの数字と本文の数字が一致するかを確かめる。

## H. 版面・線・器の作法（2026-10-22 追加）

Jinba consulting-pptx-skill（github.com/carnot-tech/jinba-consulting-pptx-skill、MIT License）の規約（slide-rules §4〜§6・§8）のうち、本ルールの骨格（A4横・2行メッセージ・NRI配色・14pt以上）と両立するものを取り込んだ。「規定は守っているのに垢抜けない」ページの多くは、箱の多用・線の太さの不統一・下半分の空きで生じている。括弧内の（FAIL）（WARN）は `scripts/check_deck.py` が検査する項目。

| No. | 作法 | 具体的に |
| --- | --- | --- |
| H-1 | **器は「見出し＋線」で作り、箱で囲まない** | 欄・列・論点のまとまりは、14pt太字の見出しと、その下の線で始める。中身は地の文と行の線で区切る。線で囲む箱は、立てたい1〜2個（推奨案・注目の列）と、ツリー・フロー・体制図・計算式の要素、自作の書式の入力枠（テンプレート集 T08・T09・T16）に限る（線の箱が4個以上でWARN） |
| H-2 | **線の太さで階層を示し、上位の線を細くしない** | スライドタイトルの線（#3F3F3F 1.25pt、全幅）≧ 欄・列の見出しの線（Gray2 1pt。結論側だけ文字色の1.25pt。紺にしない：G-6）≧ 行の線（Gray1 0.75pt）。同じ役割の線は全ページで同じ太さ・色にする |
| H-3 | **塗りか枠線のどちらか一方** | 塗りのある図形に枠線を重ねない（FAIL）。枠線を使うのは白地の要素だけ |
| H-4 | **塗りの面は、意味を言えるときに1か所だけ** | 淡い紺（Blue5）の面は、注目の行・列・「決めていただきたいこと」のどれか1か所（2か所以上でWARN）。凡例・見出し・注記で意味を言えない塗りは使わない。並べた箱の一部だけを塗る・太くするなら、その理由をページの中で言う |
| H-5 | **表は罫線を最小限に** | 列見出しの下にGray2 1pt、行の間にGray1 0.75pt。最終行の下と表の外枠には引かない（最終行の下の罫線はWARN）。縦の区切りは引かないか細い点線。ゼブラ（交互の塗り）は使わない。セルの文字は縦中央。数値の列は右（または中央）、文字の列は左にそろえる。合計の行は太い線の下に置く |
| H-6 | **箇条書きの記号は書式で付ける** | 「・」「•」を本文に文字で打たない（WARN）。階層ごとの記号は、見出し「■」、第1階層「•」、第2階層「–」で統一する（自作の書式 HG_pptFMT、パーツ集 S05）。項目が1つなら箇条にしない。1項目＝1文 |
| H-7 | **本体の下を空けない。引き伸ばしで埋めない** | 本体（スライドタイトルの線の下〜注記の上）の下30%超が空いたらWARN、40%超はFAIL。直し方の順：①行見出しを足して中身を並べる（期間・担当・終わりの条件、対象・時期・使った章など）、②内訳・前提・読み取りを足す、③型を変える、④2枚を1枚にまとめる。文字・行の高さ・箱を引き伸ばして埋めない。空きを埋めるための帯・矢印・アイコンは置かない |
| H-8 | **はみ出しと重なりを測って確かめる** | 文字が枠からはみ出す見積もりはWARN。PDFにして全ページを画像で見て、文字の重なり、注記・合計行とフッターの重なり、ステッカーと見出しの重なりを確かめる。確認したページ番号を報告に書く |
| H-9 | **浮いた要素を置かない** | ラベル・チップ・注記を、表・列・図の構造の外に浮かせない。図の補足は出所行か、図の中の該当箇所に置く。図の下に置いた一文は、無くても通じるなら消す |
| H-10 | **最初からそろう指定で組む** | 並べた要素は同じ幅・高さ・上端で組む（作ってから目で合わせない）。左右の欄の見出しの線は同じ高さ。文字の左端をそろえる。並列の行は、中身の少ない行も同じ高さにする |
| H-11 | **矢羽の下は段と1対1の列で書く** | 工程・段階の矢羽の下に別の内容を積まない。左に行見出し（期間・やること・担当・終わりの条件）を置き、各段の中身を同じ列に書く。タイトルに書いた段の数と矢羽の数を一致させる |
| H-12 | **左右の関係を示す三角・矢印は見出しの行に1つ** | 課題→打ち手、前提→帰結の向きは、見出しの行に三角を1つ置いて示す。行ごとに矢印を繰り返さない。左右の項目の対応は、同じ行に置くことで示す |
| H-13 | **意味のない矢印・線を置かない** | 矢印は順序・因果・流れを示すときだけ。線は交差させず、曲がりは1回まで。子の箱は親の真下に置く。線に付けるラベルは出発元の近くに置く |
| H-14 | **同じ見せ方を3枚続けない** | 表のページが3枚以上続いたら、見せたいのが比較・流れ・因果・位置づけのどれかを問い直し、型を選び直す（意図した連番・付録の明細は除く） |
| H-15 | **見本の段階から本物らしい値で組む** | テンプレート集（T01〜T21）は骨組みなのでXXのままでよいが、使うときは中身を入れてから見た目を判断する。【】の空欄のまま見た目を判断しない。桁と単位の合った仮の値を入れ、文字量・行の高さ・空きを確かめる（仮の値は成果物に残さない） |
| H-16 | **各論は一覧の番号と言葉を持ち込む** | 全体マップ・イシューツリーで番号を振った論点を各論で受けるときは、章名トラッカーか左のパネル（P72）に同じ番号・同じ言葉を書く。番号は後で参照するときだけ振る |

## I. 中身の厚み（2026-10-27 追加）

見た目のルールをいくら足しても、中身が計算メモのままなら薄く見える。マッキンゼーの1ページは、複数の軸のデータから「読み手が知らなかったこと」を1つ示す。設計（本体設計表）の段階で、ページごとに次を決める。

| No. | ルール | 具体的に |
| --- | --- | --- |
| I-1 | **1ページに1つ、新しい事実を示す** | 各ページは、前のページまでに出ていない事実を少なくとも1つ示す。同じ数字を描き方を変えて繰り返さない。結論の数字を本体で再掲してよいのは、エグゼクティブサマリーと結論のページの2か所まで（同じ数字が4ページ以上に出たら check_deck.py がWARN） |
| I-2 | **結論は4つの軸のうち2つ以上で裏付ける** | 時間（推移・将来の見通し、現状のまま続けた場合との比較）、外部比較（他地域・他社・自社の別事業・過去の実績との単価や規模の比較）、位置づけ（他の算定手法・選択肢・業界の幅の中のどこにあるか）、内訳（何から成り、どこが効いているか）。設計表の「分析の軸」の列に書く |
| I-3 | **根拠の図は理由そのものを示す** | 「なぜそう言えるのか」と問われたときの答えになる図にする。関連はするが理由にならない事実（例：事業費の何割を払ったか）を主役の図にしない |
| I-4 | **足りない分析は描き直しで埋めず、依頼する** | データが足りないときに、手元の同じ数字を描き直して枚数を埋めない。足りない分析と必要なデータを一覧にし、evidence-researcher かユーザーに依頼する。間に合わなければ最終報告に「入れられなかった分析」として書く |
| I-5 | **実物と並べて比べる** | 仕上げの前に、参考ページの画像（なければ `docs/reference-measurements.md` の実測値）と自分のページを同じ大きさで並べ、余白・文字の段差・線の太さ・棒の太さと隙間を比べる。ルールの合否ではなく見た目の差を見る。デッキ全体は `scripts/compare_reference.py` で、手本と同じ物差し（図の広さ・文字数・文字の段差・数字の割合・図に直接書いた文字の割合・注記の量・塗りの色数）の分布の重なりを測れる |
| I-6 | **座標は既定値から決める** | 棒の太さと隙間、ラベルの離し方、余白は目分量で決めず、`docs/reference-measurements.md` の既定値（例：縦棒の隙間は棒の幅の0.4倍）を使う |
