# スライド作成ルール（正典）

consulting-slide-builder スキルが、スライドを作る前に必ず全文を読むルール集。スキル本文と食い違う場合は、このファイルを優先する。
レビューで受けた指摘は、一般化して末尾の「G. 追加ルール」に1行ずつ足し、CHANGELOG.md に記録する。

## 着手前の確認

- 目的・成果物・範囲を3〜5行で示し、合意してから作る。
- 全ページについて「伝えたいこと」か「相手に決めてほしいこと」を1行で書く。書けないページは削る。
- 依頼者が決めたページ構成は勝手に組み替えない。組み替えるなら理由を添えて確認する。
- 定例資料は前回の**最終版**（下書きではない）を土台にし、変わった部分だけを直す。
- 同じ型を5枚以上並べるときは、代表の1枚を先に作って確認してもらう。
- 背景が分からない依頼は、デッキにせず1枚の論点整理で返す。

## A. メッセージラインの規定（最重要）

### A-1. 形式

- 1スライド1メッセージ。メッセージは**ちょうど2行**（游ゴシック UI Bold 20ptで約68〜72字、各行をほぼ埋める）。1行で終わるメッセージは情報不足、3行になるメッセージは詰め込みすぎとみなす。文字数はスライド幅と英数字の量で変わるため、最終的には実際の表示で2行ちょうどかで判断する。
- 構成は「**事実（数字入り）＋示唆（だから何か）**」。例：「○○の輸送密度は10年で4割減少し、運賃だけでは維持費を賄えない。存廃ではなく上下分離を含む運営形態の転換を検討すべき局面にある」
- 文末は「である調」で統一する。体言止め、疑問形、「〜について」、「です・ます」は使わない（相手への依頼・質問のページだけは例外）。
- **単独で読める**こと。「この」「その」「上記」で他のページを指さない。
- 主張を持たないページ（表紙、目次、章扉、会社紹介）だけは、素のラベル題でよい。
- 2行にするのは、文字を縮めて詰めるためではない。意味の切れ目で改行し、数文字だけの折り返しを作らない。

### A-2. 洗練させるための書き方

| やること | やらないこと |
| --- | --- |
| 主語と述語をはっきり書く | 「〜の状況」「〜の動向」などトピックだけを書く |
| 具体的な数字・比較対象を入れる（「2倍」「3割」「全国平均の半分」） | 「大きく」「様々な」「一定の」などの曖昧語 |
| 示唆は本体で証明できる範囲に留める | 本体にない事実をメッセージラインで主張する |
| 要素は2つまで（事実と示唆） | 「A、B、C、D」と羅列する（羅列は本体で示す） |
| 専門用語は読み手が普段使う言葉にする | 括弧書きの補足、略語の初出 |
| 前のスライドとつながる言葉を意識する（「一方で」「要因は」） | 毎回同じ言い回しで始める |
| 個数は、数そのものが主張のときだけ書く。書いた数は本体の番号と一致させる | 「3つの理由」「5つの施策」のように個数だけを示す |
| 言い切りの強さを根拠に合わせる。競合の記述は中立に | 根拠より強い断定（「唯一」「必ず」「圧倒的」） |
| 主張から書き出す | 「現状と課題：」のような分類名の前置き、「そこで」「つまり」などの話し言葉で始める、直前の依頼文の言い換え |

### A-3. メッセージラインの作り方

1. ゴーストデッキのタイトルを出発点に、A-1・A-2に沿って磨く。意味が変わる変更はしない。
2. 全メッセージラインを一覧にし、「メッセージライン一覧」として提示する（各行に文字数を付記）。
3. 一覧だけを上から読んで、結論・理由・打ち手が分かるかを自己確認する。話が飛ぶ箇所は、言葉の修正かスライドの追加を提案する。
4. **10秒テスト**：メッセージラインだけを10秒読んで、何を言いたいスライドか分かるか。**60秒テスト**：本体を含めて60秒で理解できるか。どちらかに失敗したら直す。
5. **タイトルと本体の対応**：メッセージラインの「事実」の数字は本体のどこかに必ず現れ、「示唆」はその数字から一段で言える範囲に留める。本体にメッセージと無関係な要素が残っていたら削る。
6. ユーザーの承認を得てから本体の作成に進む。

## B. 見た目の規定（NRIの骨格＋McKinseyの抑制）

### B-1. スライドサイズと余白

- 27.52 × 19.05 cm（780 × 540 pt、A4横相当）。指定があれば16:9。
- 余白：左右 0.8 cm、上 0.6 cm、下 0.8 cm。全要素をガイドに揃え、メッセージラインの位置は全ページで動かさない。
- 本体は詰め込まず、余白を残す。余白がないのは情報が多すぎるサイン。
- 位置の基準（pt、780×540基準）：メッセージブロック 上20〜92／区切り線 101／スライドタイトル 112〜134／本体 144〜486／注記・出所 494〜／ページ番号 右下。本体は12分割のグリッドに沿って置き、左右2つのエクジビットは6:6か7:5で分ける。

### B-2. フォント（NRI準拠、本体14pt以上）

**基本は14pt以上。14pt未満を使ってよいのは、注釈と補足説明だけ**とする。

| 区分 | 用途 | フォント | サイズ |
| --- | --- | --- | --- |
| 本体 | メッセージライン | 游ゴシック UI Bold | **20 pt**（全ページ同一、2行） |
| 本体 | スライドタイトル（本体の見出し、チャート見出し） | 游ゴシック UI Bold | **14 pt** |
| 本体 | 本文、キーメッセージ欄、ポンチ絵・表の文字 | 游ゴシック UI Regular | 14 pt |
| 本体 | チャートの数値ラベル、系列名、項目名（軸ラベル）、紺の注釈（CAGR等） | 游ゴシック UI／Arial | 14 pt |
| 注釈・補足 | 章名（トラッカー）、補足説明の一文、チャート見出しの単位・期間の括弧書き | 游ゴシック UI Regular | 11–12 pt |
| 注釈・補足 | ステッカー（「試算」等） | 游ゴシック UI Regular | 11 pt |
| 注釈・補足 | 注記（注））、出所（出所））、ページ番号 | 游ゴシック UI Regular | 9–10 pt |

- スライドタイトルは本文と同じサイズなので、太字＋下の細いグレー線で本文と区別する。
- 数値・英字はArialで、同じ行の和文と同じサイズにする。
- 14ptで収まらないときは、**文字を小さくしない**。文言を削る、要素を減らす、スライドを分けるの順で対応する。
- 游ゴシック UIが使えない環境ではメイリオで代替し、報告する。フォントは和文＋欧文の2種類まで。文字の強弱は色よりも太字とサイズで付ける。

### B-3. 配色（「グレーで描き、1点だけ紺」）

本体で使う色は、白・黒・グレー3段階・紺1色だけにする。

| 役割 | 色 | 使う場所 |
| --- | --- | --- |
| 紺（唯一の強調色） | #000F78 | メッセージライン、左の縦バー、本体で言いたい**1点** |
| 文字 | #000000（本文）／ #595959（補足・注記） | 全ての文字 |
| 濃いグレー | #7F7F7F | 文脈として見せたい系列、矢印 |
| 中間のグレー | #BFBFBF | 比較対象の系列、図形の線 |
| 淡いグレー | #E7E6E6 ／ #F2F2F2 | 区切り線、ごく薄い背景（必要な場合のみ） |
| 紺の淡色 | #000F78を透過85〜90% | 強調箇所を囲む面（1スライド1か所まで） |

- **強調は1スライド1点**。紺を使うのは「メッセージが指している場所」だけ。メッセージを読んだ人の目が、次に紺の箇所へ行くようにする。
- それ以外の系列・図形・見出しはグレーか黒。複数系列の区別が必要なら、グレーの濃淡で付ける。
- 赤・オレンジ・緑などは使わない。例外は「悪化そのものがメッセージ」の場合で、その1点を紺の代わりに赤（#C00000）にするときだけ。
- 塗りつぶしの色付きボックス、紺の帯に白文字の見出し、色付きパネルを並べる構成は使わない（強調が分散するため）。区切りは細い線と余白で作る。
- 確認方法：「3秒見て、強調箇所が1つだけ目に入るか」「グレースケールで印刷しても読めるか」。

### B-4. ページ構造（本文スライド）

1. **メッセージブロック（NRIの骨格）**：左端に幅約4 ptの紺の縦バー。その右に、上段「章番号＋章名」（11–12pt、#595959）、下段「メッセージライン」（20pt、太字、2行、紺）。ブロックの下に細いグレーの線。
2. **本体**：スライドタイトル（14pt太字の黒文字＋下に細いグレー線）と、エクジビット（チャート／図解／表）を1つ。
3. **キーメッセージ欄（任意）**：本体の右端または下端に、読み取るべき点を1〜3個（14pt）。各項目2行以内。枠は付けず、細い線で区切る。
4. **注記・出所**：左下。「注）」「出所）」の順（D-3）。
5. **フッター**：右下にページ番号。著作権表示・ロゴはユーザー自身の組織のもの（未指定なら空欄）。

スライドタイトルは「何のデータか・単位・期間」を示す見出しの役割に限る。それ以外の**説明行は置かない**：メッセージライン直下の言い換え、図表の上の飾りラベル、画像の下のキャプション、「POINT」「まとめ」の帯は使わない。

### B-5. その他のページ

- **表紙**：白地。左寄せでタイトル（紺、大きく）・副題・日付・組織名。写真はユーザーが用意したもののみ。
- **目次・章扉**：番号＋章名（16pt以上）を細い線で区切って縦に並べる。当該章だけ紺・太字、他はグレー。
- **エグゼクティブサマリー**：各章のメッセージラインを太字1行＋根拠の数字1行で並べ（いずれも14pt以上）、最後の提言だけを紺にする。文字主体のページはここだけ。収まらなければ2ページに分ける。
- **デッキ全体の構成**：表紙 → エグゼクティブサマリー → 目次 → 章ごとの本文 → 提言・次のステップ → 参考資料（Appendix）。本文で使わなかった分析は参考資料へ回し、本文の枚数を増やさない。
- **目次・章扉の要否**：本文が11枚以上なら目次（全体マップ）と章扉を置く。10枚以下なら置かず、章名のトラッカーだけで位置を示す。
- **締め**：「次のステップ」は、実際に依頼・合意事項があるときだけ作る。提案前の資料は相手への依頼ではなく、こちらができることで締める。正式提案は費用と次段階に進む判断基準で締める。裏表紙を置く場合は組織名と連絡先だけにする。

### B-6. 禁止事項

- NRIのロゴ、社名、著作権表示、スローガンを入れない。NRIが作成した資料に見せない。参考にするのは書体・主色・ページの骨格のみ。
- 影、グラデーション、3D、絵文字、多色のアイコンやクリップアート、装飾だけの写真、過剰な角丸。
- 塗りつぶしブロックを積んだピラミッド図やSmartArt風の図（安っぽく見える）。階層は線と文字で表す。
- 段落書きの長文。
- 下部の結論帯（メッセージラインの言い直し）、理由のない囲み・塗り、どこにも結びつかない浮いたラベル。塗りは凡例で意味を言えるときだけ使う。
- 本体の文字を14pt未満にして詰め込むこと。

## C. 本体の規定（簡潔・視覚的）

### C-1. 本体の原則

- 本体に置くのは、メッセージラインを証明する要素だけ。「あると良い情報」は後ろの参考資料へ回す。
- **文字より図**。数字はチャート、関係は図解（ポンチ絵）、比較は表で示す。箇条書きだけのスライドは作らない。
- 文字量の目安：本体の文字（チャートのラベルと注記・出所を除く）は合計120字程度まで。1つの要素に添える文は2行以内。14ptでこの量を超える場合はスライドを分ける。
- 説明に60秒以上かかるスライドは分割を提案する。
- **ピラミッド構造**：メッセージライン（結論）→ スライドタイトル（何で証明するか）→ 本体（根拠）→ 注記・出所（前提）の順に、上から下へ抽象から具体に降りる。本体の中で結論を言い直さない。
- エクジビットが2つ要る場合は**左右に並べる**（上下に積まない）。左右の見出しの高さと下端をそろえ、結論側（右）だけに紺を使う。3つ以上要るならスライドを分ける。
- **左に前提、右に帰結**。前提・定義・図は左、そこから言えること・具体例・説明は右。強い因果があるときだけ、左右の間にグレーの塗り三角を1つ置く。左右の見出しは単独で意味の通る名詞句にする（「だから〜」で始めない）。
- 右で論じる項目は、左の図のどこの話かを番号や帯で対応させる。図にない項目を右で論じない。
- 表は1枚に1つまで。比較表は**行＝観点、列＝比較対象**で統一する。行ごとの意味合いは右の別欄ではなく、表の列として持たせる。
- 比較でないものは表にしない。重なりはベン図、日程はガント、工程は矢羽、関係者の連携は流れ図、業務フローはスイムレーン（導入前の現状に提案物を混ぜない）。
- **スカスカも不可**。内容が少ないのに要素を引き伸ばして埋めない。情報を足すか型を変え、それでも少なければ中央にまとめる。本体の4割以上が空いていたら見直す。

### C-2. 本体の型（この中から選ぶ）

| 型 | 使う場面 | 強調の置き方 |
| --- | --- | --- |
| 単一チャート | 数字で証明する場合の基本形 | 言いたい棒・線だけ紺、差分やCAGRを紺の注釈で |
| チャート＋キーメッセージ欄 | チャートから読むべき点が2〜3ある | 欄の番号とチャート上の番号を対応させる |
| 左右比較 | Before/After、自社と他社、現状とあるべき姿 | 右（結論側）だけ紺 |
| ポンチ絵（関係図） | 関係者の関係、お金・モノ・情報の流れ、仕組み | 変化する箇所・課題の箇所だけ紺 |
| プロセス／ロードマップ | 手順、スケジュール | 今回決める段階・判断点だけ紺 |
| ロジックツリー | 要因の分解、論点整理 | 効いている枝だけ紺 |
| 2×2マトリクス | 優先順位、ポジショニング | 推奨象限の文字と項目だけ紺 |
| 評価表 | 選択肢・事例の比較 | 推奨する列だけ紺の細枠。評価はハーベイボール（グレー）。表は4列4行程度まで |

### C-3. ポンチ絵の作法

- 登場人物・組織は、単色の線画アイコン（グレー）＋下に短い名前（14pt）で表す。アイコンの絵柄はデッキ全体で統一する。
- 矢印には「何が流れるか」（資金、データ、人など）を短く書く（14pt）。
- 要素は6つ以内。各要素の文字は12字以内。
- アドインではPowerPointの「アイコン」を使い、Coworkでは単純な図形の組合せか単色の線画で作る。多色のイラストは使わない。

### C-4. 論理の運び（デッキ全体）

- **1枚で論理を1段だけ進める**。2段以上を詰めない。
- 課題を示したページの後には、それを解くページを対で置く（「〜は、…で越えられる」）。SCRで書く場合、課題は未達の原因だけを書き、解決は課題と1対1で対応させる。
- エグゼクティブサマリーや冒頭の表で使った行立て・用語・順番は、深掘りページでも同じにする。
- 論点を番号で宣言したら、後続ページの章名トラッカーに同じ番号を付け、どの論点の話かを示す。
- 判断を求める資料では、問いが求める形で答えるページを置く（採算を問われたら、投資を含む期間の損益で答える）。論点整理や検証計画の段階では、答えを出したように言い切らない。
- 読み手の判断を左右する分析（前提が崩れる条件、失敗の理由、感度分析）は参考資料に回さず本文に置く。
- 選んだ案の詳細は、比較して選ぶページより後に置く。

### C-5. 文章の作法

- 「連携強化」「DX推進」「自動化」「高度化」だけで済ませず、**誰が・何を・どうする**かを書く。
- 字数を削るときも主語と述語は残す。助詞を抜いた圧縮語（「需要減少対応策検討」）にしない。
- 1つの概念に1つの用語。略語は初出で説明するか、使わない。完了形と進行形（「導入した／導入中」）を取り違えない。
- AIらしい言い回しを避ける：「〜を実現」「〜を推進」「重要な役割を果たす」「多角的」「包括的」「シームレス」「〜と言えるでしょう」「さらなる」の多用、体言止めの連続。具体的な事実か数字に置き換える。

## D. チャートとエビデンスの規定（McKinsey・BCG流、think-cell風の仕上がり）

### D-1. メッセージ別のチャート選択

チャート型の誤りは分析の誤りとみなす。メッセージから逆算して選ぶ。迷ったら、**メッセージを証明できる最も単純なチャート**（多くは横棒か縦棒）を選ぶ。

| 伝えたいこと | 使うチャート | 要点 |
| --- | --- | --- |
| 時系列の変化 | 縦棒（期間が少ない）／折れ線（期間が長い） | CAGRを矢印で注記。見通しは淡色や斜線で区別 |
| 順位・大小比較 | 横棒（降順） | 注目対象だけ紺、他はグレー |
| 構成比 | 100%積上げ棒 | 系列は5つ以内。グレーの濃淡で塗り分け、注目の1系列だけ紺 |
| 構成と規模の両方 | マリメッコ（メコチャート） | 幅＝規模、高さ＝シェア |
| 増減の要因分解 | ウォーターフォール | 始点・終点は濃いグレー、要因は中間のグレー、最大要因だけ紺。増減は「＋」「−」のラベルで示す |
| 2変数の関係 | 散布図／バブル | 平均線で象限を切り、注目点だけ紺 |
| アンケート結果 | 横の100%積上げ（属性別の行） | 設問文とn数を必ず記載 |

- 円グラフ・レーダーチャート・二軸グラフは原則使わない（使う場合は理由を報告）。
- ラベルを14ptで書ける量に絞る。棒は最大10本程度、折れ線の系列は3本まで。超える分は「その他」にまとめるか、数値ラベルを注目点だけにする。

### D-2. チャートの作法（think-cell風）

- **見出し**：「何の」を14pt太字、「単位・期間」を括弧書きで11–12ptで書く。例：「国内○○市場規模の推移」＋「（億円、2015–2030年度）」。解釈はメッセージラインに書き、見出しには書かない。
- **線を減らす**：罫線なし。縦軸は消して棒の上に数値を直接書く（14pt）。横軸は細いグレーの基線1本だけ。
- **直接ラベル**：凡例は使わず、系列名を線の端・積上げの横に直接書く（14pt）。
- **棒の形**：棒の幅は間隔より太く。棒グラフの軸は0始まり。
- **注釈は1つ**：CAGRの矢印、差分の括弧（「+2.1倍」）、変曲点の吹き出しのどれか1つを紺で14ptで。数値を本文とラベルで二重に書かない。
- **見通し・推計**：実績より淡い色か斜線にし、年度に「（見込）」「（予測）」。
- **ステッカー**：数値の性格を右上に小さく（11pt）、グレーの細枠で表示（「試算」「暫定」「イメージ」「議論用」）。
- グラフ・図形は編集可能なネイティブオブジェクトで作り、画像にしない。元データはエビデンスExcelの「グラフ用」シートと一致させる。

### D-3. エビデンスの示し方

- **全数値に出所**：出所のない数値は載せない。根拠がない箇所は赤字で【要確認】（仕上げ時に全て解消する前提の作業表示）。
- **出所の書式**：`出所）発行主体「資料名」（発行年月）`。複数は「；」で区切る。加工した場合は「…を基に作成」、独自分析は「…を基に分析」。
- **注記**：定義・前提・例外は本文中に肩文字（1, 2 …）を付け、「注）1. …」と出所の上に書く。年と年度、名目と実質、税込と税抜を区別する。
- **アンケート**：設問文の要旨、n数、調査時期、複数回答かどうかを書く（注記扱い）。
- **定性情報**：ヒアリングの発言は「」で引用し（14pt）、発言者を属性（例：地方鉄道事業者 経営企画部長、補足扱い）で示す。個人名は出さない。
- **裏付けの厚み**：重要な主張は、定量データ＋事例（または有識者発言）の2種類以上で支える。ただし1スライドに詰めず、必要ならスライドを分ける。
- **数値の書式**：単位は見出しにまとめ、桁区切りを入れる。有効数字は2〜3桁、比率は小数点以下1桁まで。同じ指標は全ページで同じ単位。合計と内訳が丸めで合わない場合は注記する。
- **内訳まで出す**：合計だけでなく内訳を示す。一覧は全件を載せ、版面に入らなければ参考資料に回して本文から参照する。
- 未確定の金額・工数は「仮」と明記するか、載せない。
- スピーカーノートに、使ったエビデンスID・使ったパターンID・参考にしたページID（patterns/patterns.md）を全て記載する。

### D-4. 検算（最後まで通す）

AIが作った資料で最も差が出るのは、見た目ではなく数値の整合である。生成後に必ず行う。

- スライドに出る**計算した数値**（合計、構成比、差分、倍率、CAGR、回収年数、損益）を全て、エビデンスExcelの元データからスクリプトで計算し直し、表示値と一致するかを確かめる。結果は「検算表」（スライドNo.・表示値・再計算値・一致）にまとめる。
- 図に書いた前提条件と、計算に使った前提条件が同じかを確かめる（期間、対象、単価、名目／実質）。
- 現金にならない効果（時間削減の金額換算など）は、投資回収・キャッシュフローの計算に入れない。入れる場合は別建てにし、注記する。
- メッセージラインの数字と本体の数字、エグゼクティブサマリーの数字と本文の数字が一致するかを確かめる。
